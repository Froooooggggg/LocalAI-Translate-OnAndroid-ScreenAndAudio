同传互译 v0.7.0-beta
模型导入与故障排查（用户版）
================================================================================

这份文档只讲两件事：
  一、模型怎么装进手机
  二、装完/换过模型后出问题，怎么判断是"模型不兼容"以及怎么修

模型有两种装法，任选其一：
  1) 软件内下载：主界面黄卡上点「下载」，走 HF 镜像站直链，下完直接用（推荐）
  2) 随包 Models 文件夹：跟着发布包一起发，进「离线模型 → 导入模型」一次性吃进去


--------------------------------------------------------------------------------
〇、跑得动吗：推荐配置
--------------------------------------------------------------------------------

  项目        最低                        推荐（开发者实测机）
  ----------  --------------------------  ----------------------------
  运行内存    12 GB                       16 GB
  SoC         天玑 8300 / 骁龙 7+ Gen3    骁龙 8 Elite（8E）、天玑 9400
  存储空闲    8 GB                        12 GB 以上
  系统        Android 12 及以上           实测 Android 16 / 澎湃 OS 3
  架构        arm64-v8a                   带 Hexagon NPU 的骁龙更好

  12 GB 是硬门槛：本地大模型加载后常驻约 1.2 GB，加 ASR/OCR/系统本身，
  12 GB 属于"能跑，别开太多后台"。软件启动前会自己算可用内存，不够会弹警告。
  低配省内存：翻译后端选 NLLB-200（约 1.27 GB），识图权重选「轻量 mobile」（21 MB）。

--------------------------------------------------------------------------------

几类能力，各自吃不同的模型文件：

  能力                    需要的文件（相对 Models 的路径）
  ----------------------  ------------------------------------------------
  同传（语音 → 译文）      asr/model.int8.onnx         SenseVoice 识别

                          （换 NLLB 翻译时，llama 可以不给）

  识图（屏幕取字 → 译文）  ocr/ppocrv5-mobile-det.onnx OCR 检测（找字框）

只跑同传的话，最少 4 个文件；只跑识图，最少 3 个文件。


--------------------------------------------------------------------------------
二、把模型装进手机（三种方式，任选一种）
--------------------------------------------------------------------------------

【方式一 · 拷到手机根目录，App 自己捡】  ← 最省事，推荐

  1. 用数据线把整个 Models 文件夹拷到手机存储根目录，路径是 /sdcard/Models
     （手机上显示为"内部存储 / Models"）。
     最终结构是：/sdcard/Models/asr/...  /sdcard/Models/llama/... 以此类推。
  2. 打开 App（同传页）→ 右上角「设置」→ 往下滑到「离线模型」卡片。
     卡片上会多出一个按钮「从 Models 导入」——只有 App 真的探测到
     /sdcard/Models 时这个按钮才出现。
  3. 点它，等进度条走完。看到「导入完成：拷 N 个、跳过 M 个」就好了。
  4. 装完之后 /sdcard/Models 可以删掉，文件已经搬进 App 私有目录了。

  探测的三个位置（按顺序找，找到第一个就用）：
      /sdcard/Models
      /storage/emulated/0/Models
      /sdcard/Download/Models

【方式二 · 系统文件选择器（不用线、不用权限）】

  1. 把 Models 文件夹放到手机任意位置（比如下载目录）。
  2. App → 同传页右上角「设置」→「离线模型」→ 点「选 Models 文件夹」。
  3. 系统会弹出文件选择器，进去选中 Models 目录 → 点「使用此文件夹」→ 允许。
  4. 等进度跑完。

  注意：选中之后系统会问"允许访问此文件夹中的文件吗"，必须点允许，
  否则 App 打不开里面的文件（会显示"N 个失败"）。

【方式二·乙 · 直接选一个 .zip】

  1. 把发布包给的那个 zip（里面是 Models/ 目录）随便放手机里，不用解压。
  2. 设置 →「离线模型」→ 点「选 .zip」→ 选中它。
  3. App 会边解压边拷，进度按文件跳。

  说明：zip 里层数不限（Models/asr/... 或 asr/... 都认），按文件名后缀匹配；
  但**必须是同一个 zip**，不能把两个后端分两个 zip 传（一次只读一个文件）。

【方式三 · 开发/调试用 adb】

  adb push Models /sdcard/Models
  # 大文件建议一个一个推，断了能续
  adb push Models/llama/Huihui-Qwen3.5-2B-abliterated.Q4_K_M.gguf /sdcard/Models/llama/

  推完按方式一第 2 步点导入。

【想知道每个文件要什么 → 点「ⓘ 模型要求」】

  设置 →「离线模型」→ 导入按钮右边的「ⓘ 模型要求」。里面是这份清单的完整规格：
  · 每个文件的路径、要多大、给哪个能力用、是不是必备、现在装没装好（✔ / ✘）；
  · 五条硬规矩（文件名一字不差 / 大小 ±2% / ONNX 未加密单文件 / 子目录名不能改 / 成套给）；
  · 各后端的额外要求（gguf 结构、NLLB 三件同源、OCR det+rec 同代、ASR 成套、VAD 二选一）；
  · 三种放法（根目录 Models / 手动选目录 / 一个 zip）。
  想自己从 HuggingFace 等处找模型的人，照那一页对齐就行；软件只校验「文件名 + 大小 + 能不能加载」。


--------------------------------------------------------------------------------
三、怎么确认装好了
--------------------------------------------------------------------------------

设置页「离线模型」卡片那行字：

  必备 5/5 个（够用了）                   ← 绿色，能跑
  全部 22/22 个 · 3.93GB / 3.93GB         ← 绿色，全装好了
  必备 3/5 个（还差 2 个）                ← 橙黄，缺核心模型
  全部 5/22 个 · 1.44GB / 3.93GB          ← 灰色，装了一部分

「必备」= 同传和识图真正跑起来要的 5 个文件（约 1.53GB）：
  llama/*.gguf、asr/model.int8.onnx、asr/tokens.txt、asr/silero_vad.onnx、
  asr/gtcrn/gtcrn_simple.onnx、ocr/ppocrv5-mobile-det.onnx、ocr/ppocrv5-mobile-rec.onnx
其余 17 个都是可选项（Silero VAD 与 GTCRN 降噪已随包内置，不用管）（第二/第三识别后端、标点、高精度 OCR、NLLB、补背景）。

"已就位"的判定规则：文件存在 **且** 大小和清单一致（允许 ±2% 误差）。
所以换了别的量化版本（比如 Q8_0 换成 Q4_K_M）会显示大小不符、被视为"未就位"。

导入过程中的显示：
  [7/22] model.int8.onnx · 已拷 1024MB      ← 正在拷第 7 个，累计写 1GB
  导入完成：拷 18 个、跳过 6 个，写入 2937MB   ← 正常结束

  "跳过"= 本来就已经就位，没重复拷（可以反复点导入，不会重写）


--------------------------------------------------------------------------------
四、模型不兼容怎么排查（重点）
--------------------------------------------------------------------------------

先记住一个原则：**这个软件对模型文件很挑**——文件名、文件大小、词表、导出格式
四样必须都对得上。换个来源的同名文件经常在第三、第四项上翻车。

排查顺序永远是：看状态行 → 看日志 → 对文件 → 换回原版。


【症状 1】状态行显示 必备 5/5，但功能仍报"没找到本地模型"（只能出原文）

  原因：文件名不一样。程序是按**写死的文件名**去找的，不是扫描目录。
  怎么看：同传页「日志」会打出模型诊断串（来自 LlamaModels.diagnostics），形如
       ❌ 没有找到模型文件（期望 Huihui-Qwen3.5-2B-abliterated.Q4_K_M.gguf）
       候选目录：
         · /data/user/0/<包名>/files/models/llama  （目录不存在）
         · /storage/emulated/0/Android/data/<包名>/files/models/llama  有其它 gguf：xxx.gguf
  最后那行「有其它 gguf」就是线索：文件在，但名字不对。
  怎么办：
    a) 把文件名改成清单里的名字（大小写、连字符都要一致），别用"xxx (1).gguf"；
    b) 或者直接重新导入整个 Models 文件夹，别手工改文件名。


【症状 2】一识别/一翻译就闪退，日志里是 native 崩溃（SIGSEGV / libonnxruntime）

  原因 90% 是"半个文件"：拷贝中途没电、断线，留下一个大小不对的文件。
  程序导入时会先写 .part 再改名，正常不会出现——但手工拷进私有目录的会。
  怎么办：
    a) 检查有没有残留的 *.part 文件，删掉；
    b) 把对应文件从 Models 重新导一次（导入器看到大小不符会自己覆盖）。


【症状 3】识别结果全是乱码 / 输出奇怪的符号

  原因：模型和词表不配套。tokens.txt 必须和同一个模型包里的那份是同一套。
  典型：换了 model.int8.onnx 但没换 tokens.txt（或者反了）。
  怎么办：成对替换。清单里同一目录下的 model + tokens 要一起换。


【症状 4】OCR 能出框但读不出字，或者框里都是错字

  原因：检测(det)和识别(rec)不是同一代的模型。比如 det 用 v5、rec 用 v4。
  另外：图太小/太糊也会这样，先确认不是画面问题。
  怎么办：
    a) det 和 rec 必须同属 PP-OCRv5（文件名里带 ppocrv5）；
    b) 屏幕字特别小时，设置里把「识别权重」换成 server 版试一次
       （server 版把最长边放到 1280，小字更清楚，代价是慢 3~5 倍）。


【症状 5】换了大模型（gguf）后，翻译直接失败，日志出现
        unknown model architecture / failed to load model

  原因：gguf 的架构这个版本的推理引擎认不出来。不同量化/不同架构的 gguf
       不能混用；太新的架构要更新内核才支持。
  怎么办：
    a) 只换量化等级（Q4_K_M ↔ Q8_0）是安全的，架构别换；
    b) 实在要换，先用原版确认功能正常，再逐步替换；
    c) 换回原版：删掉 files/models/llama/ 下的新文件，重新导入 Models。


【症状 6】设置里选了「高精度 server」，但实际还是快速模式

  原因：server 那两个文件没装，程序自动退回 mobile 了（这是设计好的兜底）。
  日志会写：想要 高精度 server · 164MB，只装了 轻量 mobile · 21MB，先按它跑。
  怎么办：确认 ocr/ppocrv5-server-det.onnx 和 -rec.onnx 两个都在（一共 172MB）。
         只装了一个也算没装。


【症状 7】导入时一直显示"已拷 0MB"很久不动

  原因：还在拷大文件（gguf 1.2GB，手机上大概要 1~3 分钟）。
  怎么办：等。进度是按"文件"报的，单文件拷完才跳下一行；
         只有做完一个文件才会从 [7/24] 变 [8/24]。


【症状 8】导入显示"N 个失败"

  原因：SAF 授权没给、文件被别的 App 占用、存储空间不够。
  怎么办：
    a) 确认手机剩余空间 > 5GB（模型 3.93GB + 临时 .part 峰值）；
    b) 重新点一次「选 Models 文件夹」或「选 .zip」，这次一定点"允许"；
    c) 还是失败就走方式一（拷 /sdcard/Models 再点「从 Models 导入」）。


【症状 9】跑起来很卡、发热、或者被系统杀掉

  原因：内存/算力不够。大模型 2B + server OCR 同时上，中端机会吃紧。
  怎么办：
    a) OCR 换回 mobile；
    b) 识图页把「自动抓帧」设为"关（手动）"，只在你点悬浮键时才跑；
    c) 同传只在需要时开，别和识图同时抓屏（一个投屏只能建一个虚拟屏）。

五、排查用的日志怎么抓
--------------------------------------------------------------------------------

  手机上看：主界面（同传页）往下滑的「日志」区域，最近的动作都在里面。

  连电脑看（更全，含原生层错误）：
      adb logcat -s AST.Models AST.Vision AST.Ocr AST.Paste AST.Inpaint AST.Bubble AST.VisionSvc

  这里面能直接看到：导入每个文件的耗时和大小、OCR 装载了哪套权重、
  翻译后端是谁、"同区域自动拼接：10 块 → 5 段"这类过程信息。

  要反馈问题时，把这几行一起发过来最有用：
      "装载 OCR：…"
      "导入 <文件>：…MB，…ms"
      "导入结束：拷 N / 跳过 M / 缺 X / 失败 Y"

--------------------------------------------------------------------------------
七、隐私说明
--------------------------------------------------------------------------------

  默认配置下所有推理都在手机本地完成：录音、截屏、译文都不出设备，也不联网。
  只有你在设置里显式打开「网络API调用」并填了一个在线服务的地址和密钥时，
  译文才会发给那个服务——屏幕内容和录音仍然只留在本机。

  换模型、删 App 都不会带走数据：所有内容都在 App 私有目录，
  卸载即清空。
