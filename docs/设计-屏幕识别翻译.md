# 屏幕识别翻译（第二个模式）—— 可行性与接口预留

> 状态：**只做设计与接口预留，不实现**（用户 2026-10-17 明确要求）。
> 本文档回答三件事：能不能做、要分几步、现在该把哪些坑先留出来。

## 一、用户要的东西（原话）

> 「准备为接下来的第二个功能-屏幕识别翻译做准备。这个模式下，我们将会加载另一个识图
> 而非语音识别的模型。模型不会主动识图，会在屏幕上悬浮一个三角开始的标记。当点击此标记时，
> 触发事件：使得软件抓取当前屏幕显示内容并使识图AI进行识别，对于不同分段的文字，以不同批次
> 交给翻译模型后翻译，将输出内容输出到文本框里（如果有余量的话，我更期望一个能智能嵌字的AI，
> 这个AI会识别翻译文本以及识图AI原文，将原文直接投射上去，如果可以实现，则文本框在此模式下隐藏）
> 也就是说，这个模式期望是运行3个AI 一个识图 一个翻译 一个嵌字」

拆成可验收的行为：

1. **触发式**，不是常驻识别：屏幕上只有一个小的三角按钮（悬浮窗），点一次识别一帧。
2. **抓屏 → 识图（OCR/VLM）** 得到「分段文字 + 位置」。
3. **分批翻译**（按语义段落分批，不是整屏一次性丢给翻译模型）。
4. **回显**：先保证「文本框」路径能跑通（浮窗列出译文）。
5. **可选增强 —— 智能嵌字**：把译文直接"写回"原位置，视觉上像原文被替换掉。

## 二、可行性结论

| 能力 | 可行性 | 结论 |
|---|---|---|
| 抓屏 | ✅ 现成 | `MediaProjection` 已经为「录屏取音频」申请过，同一张 `MediaProjection` 可以再开一路 `ImageReader`（VIRTUAL_DISPLAY_FLAG_AUTO_MIRROR）。**注意：一个 MediaProjection 只能 createVirtualDisplay 一次**，要同时抓音频和画面，必须共用同一个 VirtualDisplay 的 surface |
| 识图 / OCR | ✅ 两端都有路 | ① 端侧 OCR：`PaddleOCR`/`MLKit Text Recognition`（中文包约 20~40MB，纯检测+识别，快、离线）；② 端侧 VLM：Qwen2.5-VL-3B / MiniCPM-V 2.6（2~4GB，慢，能理解版面但手机上跑不动） |
| 版面分段 | ✅ | MLKit/PaddleOCR 都给 block/line 级 bbox，按 y 排序 + 行距聚类即可切成段落 |
| 分批翻译 | ✅ 复用 | 现有 `TranslationProvider` 抽象直接用；把每段拼成 `\n` 分隔的批量请求，返回按行拆分 |
| 文本框回显 | ✅ 复用 | `SubtitleOverlay` 的 WindowManager 层直接改造 |
| **智能嵌字** | ⚠️ 分级 | 见下节，**"真·嵌字"在端侧不可行**，但"看起来像嵌字"可行 |

### 2.1 「智能嵌字」的三档现实

- **A 档（真嵌字 / inpainting）**：识别原文 bbox → 擦除 → 用扩散模型重绘背景 → 渲染译文。
  端侧没有可用的通用 inpainting 小模型（LaMa 级 200MB+，单帧 2~5 秒，且要按 bbox 逐块跑）。
  → **本阶段不做**。
- **B 档（贴片覆盖，推荐）**：按 bbox 画一个**与背景同色的不透明圆角块**（颜色取 bbox 外一圈
  像素的中位色），把译文写进去，字号自适应缩放到 bbox 内。对纯色/渐变背景几乎以假乱真，
  对照片背景会有明显色块。**这是唯一能在 1 秒内完成的方案。**
- **C 档（半透明字幕条）**：不做位置对齐，只在底部/顶部加一条半透明字幕——就是现有浮窗。
  作为 B 档失败时的兜底。

### 2.2 那"第三个 AI"到底是什么

用户的直觉是对的：**需要一个模型来判断"这段译文该放哪、放多大、要不要截断"**。
但它不必是独立的大模型 —— 用一个**规则+轻量模型**的组合即可：

1. 规则：bbox 宽高 → 目标语言字符数 → 字号（`sp = min(h*0.7, w / (字数*0.55))`）。
2. 超长处理：优先缩字号（下限 10sp），仍放不下则换行到 2 行，再不行则 C 档兜底。
3. 可选：用一个 0.5B 级别的模型做「译文压缩成短句」，只在超长时调用。

所以三个"AI"里，第三个在 MVP 阶段是**算法**，留出接口，未来可换成真模型。

## 三、性能与内存预算（骁龙 8 Elite / 16GB，按现有实测外推）

| 步骤 | 端侧耗时（估） | 备注 |
|---|---|---|
| 抓屏（1440×3200 → ImageReader） | 30~80ms | 复用已有 VirtualDisplay |
| OCR（MLKit 中文） | 200~600ms | 首帧含模型初始化 ≈ +1s |
| 分批翻译（2B@HTP0，5 段） | 300~900ms | 现有实测：首字 60~80ms/句 |
| 版面贴片渲染 | <50ms | 纯 Canvas |
| **合计** | **0.6~1.6s** | 可接受（点击触发，非实时） |

内存：OCR 模型 +40MB；若换 VLM（3B）则 +2.5GB，**与现有 2B 翻译模型同时驻留会 OOM**，
所以 VLM 路线必须做「卸载翻译模型 / 换机」二选一。

## 四、要预留的接口（现在就写进代码，实现留到下一阶段）

### 4.1 数据模型

```kotlin
// screen/ScreenCaptureSource.kt
/** 一帧屏幕截图（ARGB_8888 位图 + 屏幕尺寸），由 MediaProjection 提供。 */
data class ScreenFrame(val bitmap: Bitmap, val timestampMs: Long)

// screen/OcrEngine.kt
/** 一段被识别出来的文字及其在屏幕上的位置。 */
data class TextBlock(
    val text: String,
    val left: Int, val top: Int, val right: Int, val bottom: Int,
    val confidence: Float = 1f,
) {
    val width: Int get() = right - left
    val height: Int get() = bottom - top
}

interface OcrEngine {
    /** 识别一帧里的所有文字；实现可以是 MLKit / PaddleOCR / VLM。 */
    suspend fun recognize(frame: ScreenFrame): List<TextBlock>
    fun close()
}

// screen/LayoutWriter.kt
/** 「嵌字」抽象。A 档=inpainting 实现，B 档=贴片实现，C 档=不做。 */
interface LayoutWriter {
    /**
     * 把译文写回原位置。返回 false 表示这一块写不进去（调用方应回退到文本框）。
     * @param blocks 原文块与译文的配对
     */
    fun render(blocks: List<Pair<TextBlock, String>>): Boolean
    fun clear()
}
```

### 4.2 编排器（唯一入口）

```kotlin
// screen/ScreenTranslateController.kt
class ScreenTranslateController(
    private val capture: () -> ScreenFrame?,          // 抓屏
    private val ocr: OcrEngine,                        // 识图
    private val translate: (List<String>) -> List<String>, // 分批翻译（复用 TranslationProvider）
    private val writer: LayoutWriter,                  // 嵌字/贴片
) {
    /** 三角按钮点击 → 一帧完整流程。失败时降级到文本框。 */
    suspend fun onTrigger(): Result<Unit>
}
```

**为什么用这种"依赖全部注入"的形状**：三个 AI 都可以独立替换/关闭，
而且可以用假实现做无人值守测试（和现在 `--es auto wavtest` 的套路一致）。

## 六、必须先想清楚的风险

1. **MediaProjection 只能建一个 VirtualDisplay**：现在音频抓取已经占用了它。
   要同时要画面，必须改成「一个 VirtualDisplay + ImageReader 同步读帧」，
   或者接受「模式互斥」（语音同传 / 屏幕翻译 二选一）——**MVP 建议先做互斥**，
   实现简单且不影响现有功能。
2. **DRM / 安全窗口抓不到**：Netflix 等受保护页面截图是黑的，需在 UI 上说明。
3. **横竖屏与缩放**：bbox 是屏幕像素坐标，浮窗是 dp，转换时必须用同一份 `DisplayMetrics`。
4. **翻译注入与原文不一致**：分批翻译会丢上下文，长段落可能被切断；
   需要「按块翻译而不是按屏翻译」，块之间不合并。
5. **热区与点击穿透**：三角按钮必须可点（不能 `FLAG_NOT_TOUCHABLE`），
   但贴片层必须**完全不可点**（`FLAG_NOT_TOUCHABLE`），否则用户点不到底下的 App。
   两个窗口要分开 —— 现有 `SubtitleOverlay` 是一个窗口，需要拆成「控制层 + 展示层」。
